# Editorial homepage

The homepage introduces the city, live public sources and momentum before asking the reader to inspect a score. A lead topic receives editorial emphasis; secondary topics stay compact. Pulse Score, smoothed two-hour change, source count, confidence and lifecycle are displayed separately. Source and time filters select evidence, never alter the deterministic ranking equation.

## Read and interaction boundaries

All data comes from validated server projections. The browser requests only the public read routes, never a database, upstream source, ingestion endpoint or model. A native category selector uses the persisted semantic taxonomy: civic, traffic, technology, business, culture, food, events, weather and sports. The older editorial API buckets remain supported. An absent persisted semantic classification falls back to its existing coarse category; unknown city-life classifications are `other`, rather than invented subcategories.

Time controls query two/six/24-hour activity. Pulse Scores always compare the latest two hours with the preceding two. Search filters the returned topics locally. Category/source changes refresh the whole model, including hotspots and stream. Pending requests have a ten-second deadline; changing filters cancels the previous request and an increasing request ID prevents a late response replacing a newer selection. A failed read retains the previous snapshot and restores its filters. Valid 503 empty models show missing live collection honestly. Live reads refresh every minute.

The chart switches between recorded v2 Pulse Score snapshots within the last 24 hours and hourly distinct signal counts. Topic selection fetches bounded public detail data. Loading, errors, retry, absent history and single snapshots have explicit states. A keyboard-accessible data table supplies exact values. Demo score history is a deterministic replay at 30-minute intervals against the fictional observations available at each time; it is labeled fixture replay and is never written to live storage.

The initial chart history contains only mode, capture/evaluation timestamps, topic slug, truncation and recorded score points; source evidence and unused detail fields are not serialized twice. Chart controls and tables remain rendered on the server, while Recharts loads within 200px of the reserved plot area. The optional street map defers its JavaScript and Leaflet stylesheet until opened. Display-only source names and neighborhood centers do not import validation schemas. The 15-second live clock updates status and relative age without rerendering the dashboard or its charts.

The neighborhood view projects curated geographic centers onto a latitude/longitude grid. It does not invent city boundaries, roads or incident locations. Circle size represents explicit mention activity; stronger emerald emphasis represents the top topic's Pulse Score. Empty and citywide locations have no markers. Keyboard and pointer selection share the same focused neighborhood, counts and linked topic. The optional React Leaflet street map has rich tooltips/popups, a tile-outage fallback and retry; the geographic diagram and controls require no external service. See [Hotspot map](hotspots.md) for client boundaries, attribution and responsive behavior.

The stream displays latest-first deduplicated evidence, original HTTP(S) links, provider, domain, timestamp and publication/discovery distinction. Fictional demo titles are labeled and rendered without outgoing source links; live evidence retains original-source links. Expansion shows up to the API's 30-item limit; full counts and truncation remain visible. Footer links lead to methodology, actual GitHub repository and sources; ingestion time always refers to a successful live run.

## Truthful status and accessibility

`LIVE` requires live mode, a successful ingestion timestamp no more than 45 minutes old, no future timestamp, a readable non-stale snapshot, and no delayed read-cache refresh. A fresh partial ingestion may be live while individual source gaps remain visible. Otherwise live mode says `DELAYED`. Demo mode says `DEMO / FICTIONAL DATA` and has no successful live ingestion. The server evaluation clock initializes the first render; a client timer advances freshness after hydration, avoiding locale/clock mismatches.

An empty live dashboard distinguishes collection delays from healthy low activity and filtered-out results. Missing, stale or unavailable coverage never claims that the city is quiet. Empty live charts and geography are omitted; coverage stays visible, with a link to the explicitly fictional recording on About. Demo mode retains its interactive panels.

## Visual hierarchy

The landing viewport asks “What’s rising in Bengaluru?” and explains fast-growing topics with inspectable evidence, with GDELT, Bluesky and Hacker News named as evidence sources. Snapshot time and coverage are compact editorial annotations. Notices appear for demo, missing, stale or degraded data rather than adding a permanent healthy-state banner. The first topic has the largest headline and a wider column; secondary topics use ruled rows without miniature charts or repeated confidence labels. Scores use serif numerals, with score scale and scoring window preserved.

Search, native category/source selectors and refresh share one control row, wrapping into two rows on mobile. Main navigation remains available on small screens. Controls have 44px targets and supporting text has an 11px minimum. Charts retain exact accessible data tables, with larger axes and concise captions. Neighborhood labels use explicit offsets to avoid collisions. Empty geography omits the unused plot. Topic evidence is a ruled list rather than bordered cards, and duplicated topic metrics have been removed from the explanatory section. Methodology keeps detailed equations in a disclosure; recovery and loading states share the same restrained type and spacing. The homepage no longer repeats a three-step pipeline tutorial.

The layout supports 320px mobile through desktop, uses semantic headings, labeled controls, pressed states, live read feedback, focus outlines, safe external links and reduced-motion preferences. No stock imagery, gradients, sidebars, animation loops or paid APIs are required. Browser tests cover filters, request races, outages, retry, chart/table modes, neighborhood keyboard input, stream expansion, original links, truthful statuses, navigation, hydration, viewport overflow and WCAG A/AA checks.
# City signal edition

The paper background remains exactly `#f8f7f2`. A fluid twelve-column grid uses 1760px at 1920px (91.7% of the viewport), 1354px at 1440px and controlled 3vw gutters between. The main topic region occupies nine columns with a three-column city briefing on wide screens. At intermediate widths it recomposes into eight plus four columns; tablet moves the briefing beneath the ranked evidence; mobile places status, the lead topic, supporting rows, the explorer, map and evidence in reading order.

A short product question leads immediately into the actual evidence. The lead topic has an hourly activity trace derived from stored counts, a two-hour score and confidence, and an explicitly labeled activity count. Supporting topics use ranked rows. Collection summaries, available-source count, leading observed category and neighborhood occupy the briefing. Unsupported locations remain unknown.

NOW is the default activity selection and transparently expands to 6h/24h when shorter windows are quiet. Explicit windows stay fixed. The long operational warning is a concise summary with native disclosure; the header opens a keyboard-accessible native status dialog separating collection, enrichment, storage and publication. The full-width source ledger supports All/News/Social/Tech browsing of the loaded sample. Topic search and category/provider controls retain their validated read boundary and abort/race protection.

Typography uses self-hosted Instrument Sans variable and IBM Plex Mono via `next/font/local`, with included OFL licenses. No Google font request is made by a reader or at build time. The two browser font files total 44,800 bytes; the separate TTF used for server-rendered social images is never a browser font dependency.

Motion uses 180ms control feedback, short entry/scroll reveals, score arrival, link arrows, map selection and a 500ms chart path reveal. Reduced-motion settings disable these effects and chart animation. Animation never gates content or adds synthetic data. Native focus outlines, semantic regions, chart tables, keyboard neighborhood controls and original-source attribution remain available. Recharts and Leaflet keep separate deferred boundaries.
